# Software Design

객체지향 설계 원칙, 디자인 패턴, 아키텍처 패턴, 리팩터링을 정리합니다.

## Topics

- 디자인 패턴 (생성, 구조, 행위)
- 객체지향 설계 원칙 (SOLID)
- 아키텍처 패턴 (레이어드, 헥사고날, MVC, MVVM)
- 리팩터링과 코드 스멜
- 의존성 관리와 결합도·응집도
- 테스트하기 좋은 설계

## 작성 기준

패턴을 정리할 때는 정의와 클래스 다이어그램만 남기지 않고 다음을 함께 적습니다.

- **어떤 문제를 해결하려고 나온 패턴인가**: 패턴 없이 짰을 때의 코드와 그 한계
- **적용하면 무엇이 좋아지는가**: 변경에 유리해지는 지점
- **비용은 무엇인가**: 클래스 증가, 간접 참조로 인한 추적 난이도
- **언제 쓰지 말아야 하는가**: 과설계가 되는 경우

패턴 이름을 외우는 것보다 어떤 상황에서 꺼내 쓸지 판단하는 것이 목적입니다. 가능하면 실제 프로젝트나 프레임워크에서 그 패턴이 쓰인 사례를 함께 적습니다.
